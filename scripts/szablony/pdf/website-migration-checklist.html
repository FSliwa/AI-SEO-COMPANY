Website migration checklist

Move a site without losing rankings: tasks for before the move, launch day and the 8–12 weeks after, a hosting-only list, a 301 redirect map and a weekly tracker.

How to use this checklist

  1. Describe the migration on the card below. The type of move decides which items apply to you. Hosting change only: the “New server only” box below part C plus the baseline, testing and monitoring is enough.
  2. Assign owners and due dates to every task. Tasks without an owner are the ones that get skipped.
  3. Collect URLs and a baseline from Search Console and GA4 before you change anything. Note the export date.
  4. Fill in the redirect map (part D): one old URL = one destination URL, a 301 code and a priority.
  5. On launch day, work through part B in order and record each test result.
  6. For the first 4 weeks, crawl the site and review errors daily; until week 12, update the tracker (part E) once a week. Add every new 404 to the map.

You don’t need redirects or the Change of Address tool. Do the baseline, priority URL tests and monitoring (parts A, B and E) the same way.

D. Redirect map

Rules

  • One hop: each old URL goes straight to its final destination, with no chains.
  • 301 or 308 (permanent), not 302 or 307. Server-side redirects, not JavaScript.
  • Closest match in content, not the home page. Pages merged into one can all point to it. No equivalent = 404 or 410.
  • One URL format: HTTPS, trailing slash or not, lowercase, www or non-www.
